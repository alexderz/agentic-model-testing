Write an MCP (Model Context Protocol) server in Rust that exposes a read-only
Home Assistant instance to an AI agent.

You have a live Home Assistant REST API to work against:

  Base URL:  $HA_URL
  Token:     in the environment variable HA_TOKEN

It is READ-ONLY. GET and HEAD succeed; anything else returns 405.

Your server must speak MCP over stdio (JSON-RPC 2.0): handle `initialize`,
advertise its tools via `tools/list`, and execute them via `tools/call`.
Expose tools that let an agent explore the installation - at minimum listing
entities, fetching a single entity's state, and retrieving the configuration.

Your work is being graded on five criteria, weighted equally:

1. COMPLETENESS  - How much of the Home Assistant API is usefully exposed, and
                   how well-chosen the tools are for an agent that has to
                   explore an unfamiliar installation.
2. CORRECTNESS   - Does it build with `cargo build`? Does it speak MCP
                   correctly? Are auth, HTTP errors, timeouts and bad input
                   handled rather than panicking?
3. CODE QUALITY  - Structure, naming, readability, sensible error types.
                   No duplication, no dead code.
4. TESTS         - Real `cargo test` tests that assert something meaningful.
                   Tests must not require network access to pass.
5. USABILITY     - Clear tool names and descriptions, useful schemas, and a
                   README showing how to run it and wire it into an agent.

It must be a Cargo project that builds with `cargo build` and runs as a
stdio MCP server. Deliver whatever files the job needs.
