The Bake-off

The orrery is drawn from the data: the GPU is the sun, every model is a planet in its family's band, orbit speed is the best tokens per second that model ever reached, size is how often it ran, and a halo means it passed test 2, the MCP server. Dashed rings mark uncensored models.

01

One machine

Everything here ran on a single home workstation, one model at a time. That is the whole point: not what a cluster can do, but what fits in one consumer graphics card and how fast it goes.

02

The tests

Every test gives the agent one task and no guidance, inside a locked-down container that can reach only the model server and a replay of a real Home Assistant installation. The result is graded by running it, never by reading it.

03

Who wins, today

"Competent" means the model built an MCP server a real client could connect to and call. "Smartest" weighs how much working server and how many passing tests it produced. These picks move as results come in; the trade-off line is as important as the verdict.

The speed ladder

Every agent run, on a log scale of tokens per second averaged over the whole run (output and reasoning tokens over wall time, including tool calls and compaction). Colour and glyph are the verdict: a filled circle passed, a half circle is partial, an empty circle failed. One row is one run, and one run is one sample.

05

Fighting the compiler

The Rust MCP server task leaves a trail of builds in the transcript. Counting the compiler's own error tallies per thousand lines of final code separates models that write clean code from models that brute-force their way past rustc. A model can pass while fighting hard, so this is a second axis, not a grade.

06

Using a server, and fixing one

Building a tool and using one are different skills. Here the agent must extract facts about the recorded house through a subagent whose only tools are an MCP server's, check them against the REST API, and decide whether to trust the server. The G flavour uses a known-good server; the O flavour uses the model's own. Facts are shown as pips, the rubric as a bar.

07

Same weights, different engine

A/B speed probes of the same model on different engine builds and speculative-decoding variants, decode tokens per second. The engine often matters as much as the model, and some combinations simply fail to load.

    08

    The gallery

    One reply, no tools, one creative-coding prompt. The replies were rendered offline in a container with no network and graded on five points of 0 to 2. The frames on the cards are those offline renders at increasing times. Where the reply produced a file, "Play live" runs the model's own file, unedited, inside a sandboxed frame. A blank card means the reply spent its whole token budget thinking and never produced a file.
